# Transformation Catalog — Bronze → Silver

> Generated by `python -m scripts.build_docs` from `src/transformations/silver/specs.py` and the Silver engine. Do not edit by hand. The narrative (why, results, problems found) is in `03_silver_transformations.md`.

Silver turns each Bronze table (raw strings, ~10% dirty) into a typed, standardised, de-duplicated table `data/silver/slv_<dataset>/`. Rejected rows go to `data/quarantine/qtn_records/<dataset>/` with the rules they failed. Silver is rebuilt in full on every run (CSV storage, no in-place updates).

## The seven steps (every dataset)

| Step | What happens | Outcome |
|---|---|---|
| 1. Separate unparseable rows | Rows Spark could not parse in Bronze (`_corrupt_record` set) | quarantine, rule `malformed:row` |
| 2. Standardise | Trim every string; empty → null; casing rules per dataset (below) | values fixed in place |
| 3. Parse & cast | Strings → int / decimal(12,2) / double / timestamp / date. Timestamps accept `yyyy-MM-dd'T'HH:mm:ssX`, `yyyy-MM-dd'T'HH:mm:ssXXX`, `dd/MM/yyyy HH:mm:ss`, `yyyy-MM-dd HH:mm:ss`, `yyyy/MM/dd HH:mm:ss` (all UTC) | present-but-unparseable value → `type_invalid:<col>` |
| 4. Remove duplicates | One row per business key; keep latest `_ingestion_ts`, then latest event time, then highest `_record_hash`. Rows without a full key skip this step | extra copies removed (counted) |
| 5. Validate | Required values, types, allowed values, ranges, time order, business rules, foreign keys against already-accepted parent tables | list of failed rules per row |
| 6. Split | Any hard rule failed → quarantine (`direct`, or `cascade` when the only failure is a rejected parent). Soft rules → `dq_*` flag on the kept row | Silver / quarantine |
| 7. Derive | Add helper columns (business date, line amount, …) | extra Silver columns |

## Rule categories

Rules are named `<category>:<detail>`. When a row fails several, `primary_rule` is the first by this order.

| Priority | Category | Meaning | Outcome | Detects injected issue |
|:-:|---|---|---|---|
| 1 | `malformed` | row or JSON payload cannot be parsed | quarantine (direct) | MALF |
| 2 | `required_missing` | a required value is empty | quarantine (direct) | MISS |
| 3 | `type_invalid` | a value is present but not a valid number / date / timestamp | quarantine (direct) | TYPE |
| 4 | `enum_invalid` | a code value is outside the allowed list even after standardisation | quarantine (direct) | FMT |
| 5 | `range_invalid` | a number is outside its valid range | quarantine (direct) | NUM |
| 6 | `sequence_invalid` | timestamps are in an impossible order | quarantine (direct) | SEQ |
| 7 | `fk_missing` | a referenced parent does not exist at all | quarantine (direct) | FK |
| 8 | `business` | a business rule is violated (soft flag, except refund > payment) | flag (`dq_*`), quarantine only if hard | BIZ |
| 9 | `parent_rejected` | the referenced parent exists but was itself quarantined (cascade) | quarantine (cascade) | cascade |

Duplicates (DUP) are removed in step 4 and format issues (FMT) are fixed in steps 2–3; neither is quarantined.

## Processing order

Parents are built before children so foreign keys are checked against accepted parent rows:

1. `categories`
2. `stores`
3. `customers`
4. `weather`
5. `application_logs`
6. `products` (after `categories`)
7. `promotions` (after `categories`)
8. `delivery_partners` (after `stores`)
9. `orders` (after `customers`, `stores`)
10. `order_items` (after `orders`, `products`)
11. `order_promotions` (after `orders`, `promotions`)
12. `payments` (after `orders`)
13. `deliveries` (after `delivery_partners`, `orders`)
14. `cancellations` (after `orders`)
15. `inventory_snapshots` (after `products`, `stores`)
16. `inventory_events` (after `products`, `stores`)
17. `reviews` (after `customers`, `orders`, `products`)
18. `application_events` (after `customers`)
19. `returns_refunds` (after `orders`, `payments`)

Then **orders post-processing** fills the order columns that need child tables (see `orders`).

## Quarantine record (`qtn_records`)

| Column | Meaning |
|---|---|
| `source_dataset` | dataset the row came from |
| `source_record_id` | business key as `col=value;…` (empty value if the key itself was missing) |
| `failed_rules` | every failed hard rule, `|`-separated |
| `primary_rule` | the highest-priority failed rule |
| `severity` | `error` (direct) or `warning` (cascade) |
| `rejection_type` | `direct` (the row broke a rule) or `cascade` (only its parent was rejected) |
| `raw_record` | the original Bronze values as JSON |
| `bronze_batch_id, source_file` | where the row came from |
| `silver_run_id, rejected_at` | which run rejected it, and when |
